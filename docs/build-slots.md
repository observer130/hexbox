# 出装槽位对照（已核实）

**结论：101 站「出装」页签的四个槽位全部来自同一个接口**
`fuwen_hero_rank?championid=`（我们已在用），无需额外接口。

| 101 站显示 | 上游字段 | 形状 | 页面显示条数 |
|---|---|---|---|
| 出门装 | `itemone_json`（万分比） | 单件 | 前 5 |
| 鞋 | `itemshoes`（比率） | 单件 | 前 4~5 |
| 优先成装 | `itemcore_json`（万分比） | 三件套 | 约 10 |
| 其余成装 | **`itemone_json` 的全部 20 条** | 单件 | 20 |

## 核实过程（可复现）

页面实测数字（暗裔剑魔 266，lane=top）与上游逐一对照：

| 槽位 | 页面数字 | 上游对应 |
|---|---|---|
| 出门装 | 10.13 / 9.13 / 6.19 / 2.11 / 0.88 | ✅ |
| 鞋 | 40.92 / 10.95 / 1.24 / 0.57 | ✅ `itemshoes` |
| 优先成装 | 3.75 / 2.23 / 2.37 / **16.09** | ✅ `itemcore_json` |
| 其余成装 | 7.51 / 5.95 / 5.68 / **71.19** / **59.84** / 58.02 | ✅ **`itemone_json`** |

`itemone_json` 恰好 **20 条**，其登场率集合为
`71.19, 59.84, 58.02, 30.58, 21.01, …, 3.01, 2.54` —— 与页面「其余成装」完全一致。

> 换句话说：页面把同一份 `itemone_json` 展示了两次 ——
> 按**登场率前 5** 作为「出门装」，全部 20 条作为「其余成装」。
> 这解释了为什么两个槽位的数字会重叠。

## 两个实现细节

1. **页面按登场率降序展示**，上游原始顺序不同。
   例：`itemshoes` 原序为 `1.24 / 40.92 / 10.95 / 0.57`，
   页面显示为 `40.92 / 10.95 / 1.24 / 0.57`。实现时必须自己排序。
2. **单位不统一**：`itemone_json` / `itemcore_json` 是**万分比**（7119 = 71.19%），
   而 `itemshoes` / `itemout` / `itemover_rec` 是**比率**（0.4092）。
   混用会得到 7119% 这种荒谬数字。

## 已废弃的字段用法

`itemover_rec`（`排名_六件_登场率_胜率`，每套恰好 6 件）**官方页面并不展示**，
此前被误当作「成型六件套」写进配装方案 —— 属擅自扩大数据用途，已停用。
