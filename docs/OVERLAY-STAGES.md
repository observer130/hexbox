# 悬浮窗分阶段功能：调研与方案（修正版）

> **重要更正**：本文初版曾判定「以英雄为准的海克斯强度」与「海斗专属出装」无数据可用。
> **该结论是错的** —— 我当时只查了 `fuwen_aram_*`（全局榜单）系列接口，
> 没有看官方**海斗专属英雄页**真正调用的接口。
> 正确结论：**数据齐全**，见下。

## 一、被纠正的关键事实

官方海斗专属英雄页：
`https://101.qq.com/#/hero-detail?heroId=157&mode=hextech&lane=bottom`

这才是同类工具的参照物。它提供：

| 区块 | 内容 |
|---|---|
| 顶部 | **海克斯强度 T0**、**国服排名 #1**、**胜率 57.23%**、登场率 10.73% |
| **符文** | 该英雄的**全部海克斯**：符文名、**强度（S/A/B/C）**、**登场率**；可按**全部/白银阶/黄金阶/棱彩阶**筛选；亚索共 **126 条** |
| 技能加点 | 加点顺序 + 登场率 + 胜率 |
| **出装** | 海斗专属**出门装 / 鞋 / 核心 / 组合**，各带**胜率** |
| 最佳拍档 | 配合英雄 + 胜率 + 登场率 |

## 二、数据源（全部实测验证通过）

**同一个接口**即提供上述全部数据：

```
https://mlol.qt.qq.com/go/battle_info/odp_proxy/fuwen_hero_rank?championid=<英雄ID>
```

> 注意：这是 `fuwen_hero_rank`（单英雄），**不是** `fuwen_aram_hero_rank_v2`（全局榜）。
> 我此前只用了后者，因此误判"无数据"。

### 返回字段（实测样张，亚索 157）

| 字段 | 含义 | 格式 |
|---|---|---|
| `augment_json_irank` | **该英雄的全部海克斯强度** | `排名\|英雄ID\|海克斯ID\|等级\|登场率\|强度` 以 `#` 分隔 |
| `augment_json` | 同上，按稀有度分组 | `kGold:…&kPrismatic:…` |
| `itemone_json` | 出门装（单件） | JSON：`itemone`/`winrate`/`showrate`（万分比） |
| `itemout` | 出门装组合 | `itemIds$登场率$胜率` |
| `itemshoes` | 鞋 | `itemId$登场率$胜率` |
| `itemcore_json` | 核心组合 | JSON：`itemcore`（`&` 分隔）/`winrate`/`showrate` |
| `itemover_rec` | 完整出装组合 | `排名_6件装备_登场率_胜率` |
| `championid_json` | 最佳拍档 | `英雄ID\|胜率\|登场率\|排名` |
| `skill_json` | 技能加点 | JSON：加点序列 + 登场率/胜率 |
| `dtstatdate` | 统计日期 | `20260925` |

### 关联验证（全部通过）

| 检查 | 结果 |
|---|---|
| `augment_json_irank` 条数 | **249 条**（页面显示 126 条，应为去重或分页差异，待复核） |
| 海克斯 ID → 本地国服图鉴 | **249 / 249 命中**，中文名正确（灵魂虹吸、升级：无尽之刃…）✅ |
| 装备 ID → 本地 `items` 表 | 鞋 3006/3111/3047/3009 **全部命中** ✅ |
| 覆盖英雄 | 任意英雄按 `championid` 拉取即可 |

## 三、已知的官方口径细节

1. **`lane` 参数**：海斗页仍传 `lane=bottom`（海斗无真实分路，官方复用 BOTTOM 口径）。
   实测不同 lane 返回不同出装，`lane=ALL` 无数据。→ **采用 `lane=bottom`（与官方一致）**。
2. **`itier` 段位**：页面用 `26`（白金+）拉英雄详情、`255` 拉部分数据。
   建议跟官方一致或统一用 `255`，待定。
3. **符文表的「登场率」**：该表列是**登场率**（pick rate），不是胜率 —— UI 文案不能写错。

## 四、本次确认的范围

| 阶段 | 显示内容 |
|---|---|
| **选人阶段** | **仅** Tier 层级 + 胜率（其余不显示） |
| 最佳拍档 | **不显示** |
| 避坑海克斯 | **不做** |
| **局内出装建议** | **必须做** |
| 符文（该英雄的海克斯强度） | 明确要求"选人阶段只有 Tier+胜率"，故**不在选人阶段显示**；是否放局内待确认 |

### 出装获取方式（已确认）

**sync 时预抓进本地**，悬浮窗保持只读本地、离线可用。

预抓范围：因是 `(英雄 × lane)` 维度，全量 245 英雄 × 1 lane(bottom) = 245 次请求，
每次约 13KB → 约 3MB。**可接受**，一次 sync 完成。

## 六、已确认的决策

| 项 | 决定 |
|---|---|
| 选人阶段 | **仅显示胜率**（Tier 不做） |
| Tier 强度分级 | **不做** —— 官方页的 T0 不在任何接口返回里，是前端计算；不自己编公式 |
| 符文（海克斯强度 S/A/B/C + 登场率） | 放**海克斯选择阶段**（局内） |
| 出装 | **必须做**，放局内 |
| 最佳拍档 | 不显示 |
| 避坑海克斯 | 不做 |
| 预抓范围 | **245 英雄全抓**（约 3MB），sync 时完成，悬浮窗离线可用 |

### 关于 Tier 的查证记录（避免重复踩坑）

官方海斗英雄页顶部渲染 `T0.png`，但实测**任何接口都不返回该字段**：

| 候选来源 | 亚索结果 | 与页头 T0 一致 |
|---|---|---|
| `lol_101strategy?lane=ALL` | T3 / 50.56% | ❌（峡谷口径） |
| `lol_101strategy_newlane`（分路） | T3 / T3 / T4 | ❌ |
| `fuwen_aram_hero_rank_v2` | #1 / 57.23% | 数值一致但**无 tier 字段** |
| `fuwen_hero_rank?championid=` | 无 tier 字段 | ❌ |

结论：T0 是**前端计算**的，官方未公开口径。**不自行编造公式**，
改为一律不显示 Tier（胜率本身已是官方直出、可核对）。
