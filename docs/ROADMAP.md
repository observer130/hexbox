### 2.4 LCU 与硬约束的落地

- `isBrawlSession()` 用官方常量判定（`gameMode === 'BRAWL'` 或 `queueId === 2300`）。
- 凭证获取：进程命令行（需管理员）→ lockfile 递归查找 → 监听端口探测。
- 国服实测坑已记录：`LeagueClient\lockfile` 为 0 字节，不可依赖。
- 硬约束真实成立：全程只读进程**元数据**与**窗口几何**（`GetWindowRect`），
  未打开游戏进程句柄、未读内存、未注入、未解析封包。

## 三、本轮修复的缺陷

### 3.1 时间炸弹测试（已修复）

`packages/provider-tencent/src/index.test.ts` 中的
「HTTP 失败后回退到更早日期」用例，把 T-1 写死为 `20260924`。

但实现里的候选窗口是**按真实当天日期动态生成**的：

```ts
// fallbackStatDates(): 从「昨天」起往前取 5 天
Array.from({ length: 5 }, (_, i) => new Date(Date.now() - (i + 1) * 86_400_000) ...)
```

于是日期一旦漂移，首个候选日就不再是 `20260924`，mock 的 502 分支永不触发，
`n >= 2` 断言失败——**测试随日历自动变红，与实现无关**。

修复方式：让"首个候选日"**动态**失败，而不是写死某一天：

```ts
const firstCandidate = Array.from({ length: 5 }, (_, i) =>
  new Date(Date.now() - (i + 1) * 86_400_000).toISOString().slice(0, 10).replace(/-/g, ''),
)[0]!
```

同时把断言从"某一固定日期被请求 ≥2 次"改为"尝试过 ≥2 个不同日期"，
使断言真正检验**回退行为**而非某个日期常量。

> 这类缺陷值得警惕：它平时是绿的，只在特定日期附近爆红，
> 复盘时极易被误判为"回退逻辑坏了"。

### 3.2 一处观察（非缺陷）

`mergeDatasets()` 合并策略是"后者只补前者没有的部分"，且**只处理 `hextechs`**。
新增数据源时若需要合并其它字段，这里会静默丢弃——见待办 T6。

## 四、真正的空白：悬浮窗的辅助内容

悬浮窗当前在 `InProgress` 阶段渲染的是：

> · 图鉴 / 胜率面板尚未实现（见开发计划）
> · 不识别你当前被提供的 3 个海克斯 —— 官方无此数据
> · 不替你做选择

这三行诚实，但也说明**对局中它帮不上任何忙**。这就是下一阶段的主战场。

关键判断：**别急着上 OCR**。本地已有 211 条海克斯胜率 + 1266 条英雄适配关系，
在不识别"你被提供了哪 3 个"的前提下，仍可提供大量**有依据**的辅助
（见 P1）。OCR 是最后一块拼图，不是第一块。
