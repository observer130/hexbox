# P1 真机验收清单（顶栏格数 + 一局全链路）

> 这份清单只覆盖**只能在真机判定**的项。跑一次（约 20 分钟）能把 5 个待验点一起收掉。
> 代码侧已就绪并全绿（`pnpm test` 1100 项）；这里要的是"真机上确实成立"。

## 0. 准备

```powershell
# 需要：管理员权限 + 真实桌面（CI 跑不了）
pnpm install
pnpm sync          # 数据（首次约几分钟）
pnpm templates     # 头像模板 + 名字指纹
```

- 另开一个终端窗口，把日志 tee 到文件：`$env:HEXBOX_LOG_FILE='debug/p1.log'`
- 1.2 需要一张**第二阶段整屏截图**（含顶栏），Win+Shift+S 即可

## A. 顶栏到底几格（1.2）

**背景**：`packages/vision/src/confirmed.ts` 的注释写"扩成 **11** 格、最左'可用'格在
`549/2400 ≈ 0.2286`"，但常量是 `x0: 659/2400`、`count: 10`（算术上右缘也不自洽）。
差的正是"可用区"那格——只有它被占用时，占用数会读成 **0**，阶段被判成一阶段。

**步骤**

1. 启动：`pnpm dev:overlay`
2. 进选人，**选中英雄**进入第二阶段（顶栏出现"可用"方头像，至少 1 个）
3. 在日志里找这一行：

```
第二阶段(locked): 顶栏占用 N 格, 识别成功 M 格
```

4. 同时截图（把顶栏拍清楚）

**判读（照表办事，不用猜）**

| 现象 | 结论 | 动作 |
|---|---|---|
| `N=0`，但截图上顶栏**确实有 ≥1 个头像** | 11 格标定是对的，代码漏了最左格 | 改 `TOP_BAR_ROW` 为 `x0: 549/2400`、`count: 11`，同步 `confirmed.test.ts` 的两处断言（`10 格` / `x0 === 659/2400`），重跑 `pnpm test` |
| `N` 恰好等于截图上肉眼数的头像数 | 代码是对的，注释的"11 格"是过期设想 | **只改注释**：把"扩成 11 格"改成"实测 10 格已覆盖到可用格"，**不要动常量** |
| `M < N`（识别成功少于占用） | 另一类问题（暗色头像阈值/模板），单独记 | 附截图 + 该行日志 + 前后各 20 行 |

> 这一项**必须**有截图才能定案：代码里两种可能（常量错 / 注释错）都说得通。

## B. 一局全链路（1.4）

```powershell
$env:HEXBOX_AUGMENT_RECORD='1'
pnpm --filter @hexbox/overlay debug:augment
```

打完一局后 **Ctrl+C**。看到下面两行即表示干净收工（哨兵路径已在 2026-11 对齐）：

```
[launcher] 收到 SIGINT → 通知录制程序收尾（写好产物再退出）…
[record] 🎥 会话录制收工：门控帧 N / 原生帧 M → debug\augment
```

> 若只看到 launcher 那行、4 秒后被强杀：把 `debug/augment/` 的目录列表发回 —— 说明哨兵又没对上。

**逐项对照**

| # | 观察点 | 通过标准 | 失败时抓什么 |
|---|---|---|---|
| B1 | 面板出现次数 | 一局内 `面板出现` 次数 = 实际选海克斯次数（通常 4），`面板消失` 同数 | 日志里 `面板出现/消失` 那几行 |
| B2 | 假阳性 | 非面板时刻**没有** `面板出现`（尤其团战/回城） | 该时刻前后 30 行 |
| B3 | 标签位置 | 每张卡的字母在卡下方居中、三张互不重叠、**不整体下移**（对照上一版缺陷） | 一张屏幕截图（对比用） |
| B4 | 单卡重随 | 手动重随一张 → 日志出现 `单卡刷新`，该卡字母/选取率跟着变；认不准时**不画**而不是沿用旧字母 | 日志 + 截图 |
| B5 | **离开选人后不留标签** | 进入对局后画面上**不再出现**选人阶段的胜率标签（本次修复的验收点） | 截图 + 日志中 `[hexbox:vision] 推送` 最后 10 行 |
| B6 | **副屏坐标** | 把客户端拖到副屏再进选人/对局，标签仍贴着卡片/顶栏（本次修复的验收点） | 截图（含任务栏，能看出是副屏） |
| B7 | 收工状态 | 对局结束 → 标签清空、托盘菜单回到"未在对局中" | 托盘 tooltip 截图 |

> B5/B6 是 2026-11 那两个修复的真机验收点；**只要其中一条不过，对应的代码改动就要回看**。

## C. 回放复核（离线，随时可跑，不需要游戏）

```powershell
# 直接回放最新一场
node --experimental-strip-types scripts/replay-session.mts debug/sessions/<最新目录>

# 导出一份自包含会话（帧 + 索引 + golden 一起），再回放
node --experimental-strip-types scripts/replay-session.mts debug/sessions/<最新目录> --dump=debug/dump-check
node --experimental-strip-types scripts/replay-session.mts debug/dump-check
```

看三行就够：

| 行 | 期望 |
|---|---|
| `门控：采样 N 帧（… 缺口 0 次 …）` | **缺口 0**（有缺口说明帧库不完整，"改节奏的结论要打折"） |
| `整批识别锚点：命中 X / golden Y 条（缺 0、回放多 0）` | **缺 0**（"回放多"允许少量） |
| `识别调用 N 次 vs golden M 条` | 差值 ≤2 视为重试噪声（不报警）；**>2 会出现在 diff 里** |

> 历史会话 `20261012-213155-InProgress` 的基线（2026-11 实测）：515 帧 / 缺口 0 /
> 边沿 2 命中 2 / 重随 5 命中 5 / 识别 8 vs golden 7（差值 1，不报警）。

## D. 失败时发回什么

1. `debug/p1.log`（或整段终端输出）
2. 截图：A 项的顶栏图 + B3/B5/B6 各自的画面
3. 会话目录 `debug/sessions/<时间戳>/` —— 环境变量快照已自动脱敏，不含 LCU 令牌

> 重新录制前先把旧的 `debug/augment` / `debug/sessions/<ts>` 改名或删掉，避免覆盖上一场的证据。
