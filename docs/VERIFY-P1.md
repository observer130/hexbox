## B. 仍然必须上机的（最小清单，一局 + 两次点击）

| # | 观察点 | 通过标准 | 为什么回放测不了 |
|---|---|---|---|
| B1 | **标签真的画在屏幕上了** | 选人/局内都能看到文字（不是只有日志里有） | 画布可见性、置顶、z-order 是 Electron 窗口行为，回放不创建窗口 |
| B2 | **标签位置看起来对** | 贴着卡片/顶栏，不重叠、不整体偏移 | 回放能算几何数字，但"看起来对不对"要人眼 |
| B3 | **退出干净** | 托盘菜单「退出」→ 进程真的消失；关窗口只隐藏 | 托盘/单实例/退出清理，回放完全不涉及 |

另外两个**顺手看一眼**（不进验收清单，但值得记录）：真机帧率（`~18ms/帧` 是否退化）、
以及一局结束后托盘 tooltip 是否回到"未在对局中"。

## C. 回放基线（2026-11-08 实测，三场留存会话）

```
20261012-213155  门控 515 帧 / 缺口 0 / 面板 63 帧 / 出现 2 消失 2 / 重随 5 / 识别 8 vs 7  → ✔ 逐项一致
20261012-225204  门控 267 帧 / 缺口 0 / 面板 48 帧 / 出现 2 消失 2 / 重随 2 / 识别 4 vs 4  → ✔ 逐项一致
20261012-230239  门控 561 帧 / 缺口 0 / 面板 80 帧 / 出现 4 消失 4 / 重随 8 / 识别 13 vs 12 → 面板帧 80 vs golden 77（±3，帧库格点不同相，已由判据容忍）
```

判读标准：

| 行 | 期望 |
|---|---|
| `门控：… 缺口 0 次` | **缺口 0**（有缺口说明帧库不完整，"改节奏的结论要打折"） |
| `整批识别锚点：…（缺 0、回放多 0）` | **缺 0** |
| `认定面板的帧数不一致` | 只允许 ±几帧（帧库格点相位）；差得多说明判据或帧库有问题 |
| `识别调用 N 次 vs golden M 条` | 差值 ≤2 视为重试噪声；>2 会进 diff |
