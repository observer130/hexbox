# hexbox v0.2.0

**功能版**：这一版把"S5.7 会话录制/回放"收尾成可用基建，并借鉴同类工具的四项工程做法
补齐了四块能力 —— **LCU 事件订阅**（相位变化不再等最多 2 秒）、**标签悬停提示详情**、
**重连恢复**、以及把"已发货的失败清单"变成**可 grep 的排查表 + 三个自测场景**。

> 与 0.1.1 相比：托盘四项菜单、日志位置、数据快照口径、安装形态（NSIS 每用户安装 +
> 便携版）**都没有变**；**没有**加入"自动接受对局"（本次明确不做）。
> 仍然**不注入 / 不读内存 / 不打开游戏进程句柄 / 不解析封包**，只用官方公开面
> （LCU 本地 REST、2999 局内数据接口、截屏识别官方 UI）。

## 这一版新增了什么

### 1. LCU 事件订阅：相位变化的延迟从"最多 2 秒"降到一次本地往返

以前靠每 2 秒轮询一次 `gameflow-phase`，所以"进选人/进对局"最坏要等 2 秒才开始取帧、
画标签。现在订阅了 LCU 的本地事件通道（`OnJsonApiEvent_lol-gameflow_v1_gameflow-phase`）：

- 事件到达 → **立刻复查一轮**，相位一变马上跟上；
- 事件**只负责叫醒**：相位判定仍然只有阶段门（`stageGate`）一条通路，
  "离开要连续确认"这些规则一行都没改；
- **2 秒轮询照旧保留**：事件通道没连上、或客户端不推事件时自动兜底（不是二选一）；
- 断线按 1s→2s→4s…最多 30s 退避重连，只保留一个待执行的重连。

实现上没有引入新依赖（仓库原本没有 WebSocket 库，Electron 33 的 Node 20 也没有全局
`WebSocket`），而是一个 ~300 行的 RFC6455 帧编解码 + WAMP 订阅，按字节向量做了单测。

### 2. 标签悬停提示详情（点击仍然 100% 落到游戏）

那块全屏透明画布一直是"永久穿透"的（`setIgnoreMouseEvents(true, { forward: true })`），
只是我们一直没用它送进来的鼠标移动。现在：

- 鼠标停在**选人胜率标签**上 → 弹出详情：胜率、选取率、榜单排名与名次变化、
  **统计日期**、数据来源；
- 鼠标停在**局内强度标签**上 → 弹出详情：档位、本局英雄、该英雄口径的选取率、
  "识别自屏幕"与**"评级来自官方单英雄强度表（不是本局给你的选项）"**；
- 提示框会自己避开屏幕边缘（贴底自动翻到标签上方、贴边夹进窗口），
  鼠标移开立刻消失（**不留鬼框**）；
- 画布依旧不吃任何点击 —— 悬停只"看"，游戏输入一点不受影响。

### 3. 重连恢复（客户端重启型断线）

客户端重启会走 `Reconnect` 相位再回到对局中。这期间真实发生过的三件事现在会自动处理：

| 时机 | 动作 |
|---|---|
| 进入 `Reconnect` | **只记账**，不做任何动作（重连期间乱动只会更糟） |
| 回到对局中（`InProgress`）且刚重连过 | **恰好恢复一次**：本局链路若曾被判"本局不重试"则重置；若链路"在跑"但抓帧早已失效（僵尸会话）则停掉重建 |
| 选人 / 开局 / 大厅 / 结算相位 | 直接复位重连记账（避免"选人 → 进局"这种**正常**转移被误判成重连） |

英雄身份也一起补：优先用本局缓存，缓存没有就去 2999 兜底重试（3 次 × 2 秒，
每次重试前重建 2999 客户端）。试满仍拿不到就**不画**（宁缺勿错）。

### 4. 失败清单 → 排查表 + 自测场景

把同类产品**已发货**的安装包里那张线上反馈分类表（"选人阶段不显示 / 海克斯阶段不显示 /
两个阶段都不显示 / 玩了几局后不显示 / 显示信息偏移"）抄成了我们自己的排查手册：
每个症状 → 可能原因 → **搜哪一行日志** → **做什么动作**。它由代码生成
（有单测锁住字面量，并与我们真实的日志文案做了跨模块校验），所以文档与日志不会漂移。

覆盖窗自测（`HEXBOX_LABEL_OVERLAY_TEST=1`）现在还会**自己跑三个场景**并给出结论：

```text
✅ 悬停提示框：悬停前 0 像素 → 悬停中 50687 像素 → 移开后 0 像素
✅ 清空无残留（长会话不累积）：推空后 0 / 0 像素，再推回 134972 像素
✅ 改尺寸后画布跟随窗口：画布 3441x1368 = 期望 3441x1368（窗口内 2294x912，dpr 1.5）
```

跑完会把**悬停提示框长什么样**截一张图存到 `debug/label-overlay-hover.png`，
并打印上面那张排查表。任何一个场景失败，自测就返回**非零退出码**。

## 会话录制 / 离线回放（S5.7 收尾）

这一版把"再打一局才能验"变成"跑一次回放"：

- **闭环回放**：把录制的一局（门控帧 + 原生帧 + 2999 采样 + 面板边沿）喂给**线上同一个
  控制器**，虚拟时钟驱动 —— 报告给门控边沿、整批识别锚点、单卡刷新、标签推送/清空，
  并与录制当时的 `report.json` 做**双向逐项比对**；
- **重连判定回放**：把录到的**相位序列**喂给线上那条重连纯判定。真实录制里没有
  `Reconnect`，所以 `恢复动作` 必须为 **0**（不为 0 = 对局中途误触发，会让链路自己重启）；
- 三种会话的实测结论：两局 `✔ 逐项一致`，第三局仅"认定面板 77 vs 80 帧"这一条
  已知的帧库格点差（**改动前后跑出来完全一样**，已确认与本次改动无关）；
  硬指标（漏开 0 / 缺重随 0）三局全绿。

## 托盘（唯一的交互入口，与 0.1.1 相同）

右键任务栏托盘里的 hexbox 图标，菜单**只有四项**：

| 菜单项 | 可点 | 说明 |
|---|---|---|
| `状态：选人中 / 局内 / 等待客户端 …` | 否 | 当前阶段 |
| `数据更新时间：2026-10-05（统计日期）` | 否 | 内置数据快照的官方统计日期 |

## 日志与数据

- **日志**：`%LOCALAPPDATA%\hexbox\logs\overlay.log`
  （超过 4 MB 自动轮转为 `overlay.log.1`；启动时日志第一行会打印它的**绝对路径**）。
  本版新增两行值得 grep 的日志：`⚡ LCU 事件订阅生效`、`🔁 重连`。
- **数据目录**：`%LOCALAPPDATA%\hexbox\data\`（可选；放进去的 5 个 json 会覆盖安装目录里的快照）。

## 已知问题与限制（如实）

1. **LCU 事件订阅在"读不到凭证"时不会生效**：WeGame 版客户端的 lockfile 是 0 字节，
   非管理员读不到进程命令行 —— 此时仍然只靠 2 秒轮询（功能正常，只是慢一点）。
2. **重连恢复的触发条件只在"客户端重启型重连"**：本机录制里没有出现过 `Reconnect`，
   所以这条路径的**在线表现**尚未在真机上验到（纯判定与回放判定都有单测覆盖）。
3. **悬停提示框不换行**：超长文案按框裁剪（宽度上限 320 DIP）；文案由程序生成，长度可控。
4. **便携版不支持自助更新**：`检查更新` 下载并启动的永远是 **NSIS 安装包**。
5. **数据是快照，不会自己更新**：内置的是打包当天的官方榜单/强度表（菜单第 2 项能看到统计日期）。
6. **没有任何代码签名**：见上面的 SmartScreen 一节。
7. **每次启动都会弹 UAC**：Windows 不允许对程序记住"总是放行"。
8. **强度表只覆盖官方公布过的那部分海克斯**：官方每英雄的强度表只有 95~162 行，
   卡片上的海克斯若不在该英雄的官方表里（或 OCR 无法确认），**不会画任何字母**。
   局内显示的口径始终是"官方统计里这个英雄拿这个海克斯的数据"，数字是**选取率**，不是胜率。
9. **选人卡片几何只覆盖 2 张与 3 张两种排布**；不符时**一张卡片标签都不画**（不画到错位置）。
10. **首次启动"什么都看不到"是正常的**：没有客户端或不在选人/对局阶段时，屏幕上不会出现任何东西，
    程序只是一个托盘常驻进程 —— 请先看托盘状态项与日志。

## 反馈

出问题时请把 `%LOCALAPPDATA%\hexbox\logs\overlay.log` 一起发回。
日志里已经带上了排查所需的全部字段：阶段、凭证来源、门控边沿、识别与标签的逐项原因、
LCU 事件订阅状态、重连动作，以及每一次"清空强度标签"的原因。
